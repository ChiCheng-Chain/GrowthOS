## 数据层增量(本阶段唯一新增 DAO 方法)

SampleDao / SampleRepository 需补两个查询(F1 + F5),其余 F2/F3/F4 现成:

### F1 本周样本数(按时间窗口 count)

```kotlin
// SampleDao
@Query("""
    SELECT COUNT(*) FROM samples
    WHERE (:domainId = 0 OR domainId = :domainId)
      AND recordedAt >= :startMillis AND recordedAt < :endMillis
""")
fun observeCountLastNDays(domainId: Long, startMillis: Long, endMillis: Long): Flow<Int>
```

返回 `Flow<Int>`(非 suspend),随样本变化自动推送。domainId=0 表示全局。

### F5 建议关注的高频可控错误(高频 + 可控交叉)

```kotlin
// SampleDao
@Query("""
    SELECT s.errorTypeId AS errorTypeId, et.name AS errorTypeName, COUNT(*) AS count
    FROM samples s
    INNER JOIN error_types et ON s.errorTypeId = et.id
    WHERE (:domainId = 0 OR s.domainId = :domainId)
      AND s.recordedAt >= :startMillis AND s.recordedAt < :endMillis
      AND s.attribution = 'CONTROLLABLE'
    GROUP BY s.errorTypeId
    ORDER BY count DESC
    LIMIT 1
""")
fun observeTopControllableErrorType(domainId: Long, startMillis: Long, endMillis: Long): Flow<ErrorTypeCount?>
```

返回最近 N 天内、可控归因样本中频次最高的单个错误类型;无则 null。复用 [ErrorTypeCount](../android/app/src/main/java/com/growthos/app/data/local/relation/ErrorTypeCount.kt) POJO。

SampleRepository 补对应 `observeCountLastNDays(n, domainId)` 与 `observeTopControllableErrorTypeLastNDays(n, domainId)` 便捷重载(内部用 `TimeUtil.lastNDaysRange`)。

## 状态设计(WeeklyViewModel)

```kotlin
data class WeeklyUiState(
    val days: Int = 7,                          // F6 时间范围(7/14/30)
    val domainFilter: DomainFilter = DomainFilter.All,  // F7 领域选择
    val sampleCount: Int = 0,                   // F1
    val topErrors: List<ErrorTypeCount> = emptyList(),  // F2 前三
    val controllableRatio: ControllableRatio? = null,   // F3
    val highestEmotion: SampleWithErrorType? = null,    // F4
    val suggestedError: ErrorTypeCount? = null,         // F5 建议关注
    val availableDomains: List<Domain> = emptyList()    // F7 选项(可见领域)
)

sealed interface DomainFilter {
    data object All : DomainFilter          // 全部领域(domainId=0)
    data class Single(val domainId: Long) : DomainFilter
}
```

- `days` 与 `domainFilter` 是 MutableStateFlow(用户选择)。
- 五项数据流:`combine(days, domainFilter, availableDomains) { ... }` → `flatMapLatest { (days, filter, _) -> combine(5 个查询流) }`。days/filter 变则切到新查询。
- domainId 解析:`DomainFilter.All → 0`,`Single(id) → id`。
- F1/F2/F3/F4/F5 各调对应 Repository 方法,传 days 与 domainId。
- `availableDomains`:`DomainRepository.observeVisible()`(F7 选项)。
- 初始值:days=7, filter=All。

## 数据流

```
combine(daysState, domainFilterState) → flatMapLatest { days, filter ->
    val domainId = if (filter is All) 0 else filter.domainId
    combine(
        observeCountLastNDays(days, domainId),
        observeTopErrorTypesLastNDays(days, domainId, limit=3),
        observeControllableRatioLastNDays(days, domainId),
        observeHighestEmotionLastNDays(days, domainId),
        observeTopControllableErrorTypeLastNDays(days, domainId)
    ) { count, top, ratio, emo, suggested -> WeeklyUiState(...) }
}
→ WeeklyScreen collect → 五项渲染

切时间/领域:days 或 filter 变 → flatMapLatest 切新查询 → 五项重算
```

## 关键决策

### D1 F1 本周样本数用 Flow<Int> 而非 suspend count

样本数随录入变化应自动刷新,用 `Flow<Int>`(observeCountLastNDays)而非 suspend 一次性 count。对齐阶段 0~3 所有统计均 Flow 的模式。DAO 加一条 COUNT 查询(阶段 0 没建,因为当时没周复盘需求)。

### D2 F5 建议关注用单独交叉查询,不复用 F2

F2 高频前三不区分归因;F5 要"高频 + 可控"交叉。不复用 F2 过滤(那样要在 UI 层再查每个错误类型的可控数,N+1)。直接一条 SQL:`WHERE attribution='CONTROLLABLE' GROUP BY errorTypeId ORDER BY count DESC LIMIT 1`,一次出结果。这是阶段 4 第二个数据层增量。

### D3 时间选择器只给三档,不做任意起止

7/14/30 天三档 chips,不做人选起止日期。理由:自用周复盘以"最近 N 天"为主,任意起止增加交互复杂度且 MVP 未要求(N-004 不过度复杂)。可演进:后续要对比某两周再加。

### D4 跨领域用 domainId=0,单领域用用户在复盘页选的

不复用 SelectedDomainStore(那是领域页的选中态,复盘页是独立视图,默认应看全局)。复盘页顶部 F7 chips 独立维护 domainFilter,默认 All。理由:周复盘是"跳出单领域看全局趋势",默认全局更合理;用户可主动缩到某领域。

### D5 删 SampleStub

阶段 3 清了 DomainScreen 的 errorDistribution 引用,阶段 4 清 WeeklyScreen 的 weeklySampleCount/controllableRatio/topErrors/highestEmotionSample 引用后,SampleStub 无残留,删文件。
