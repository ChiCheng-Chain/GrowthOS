# GrowthOS 阶段 6:原则沉淀 需求文档

## 文档定位

本文件是二期阶段 6(原则沉淀)的细化需求。需求基线以 [MVP 需求文档](MVP需求文档.md) R-012 为准,本文件不重复原文措辞,只把它落地到可实施的交互与边界。技术实现见配套《阶段6-原则沉淀-设计》。前置依赖:阶段 0~5 已落地。

阶段 6 是闭环第 8 步,也是 MVP 闭环的最后一步——从多个样本或训练周期沉淀出可迁移的认知(原则),可选关联领域/错误类型/训练项/样本。前七步是"记录 → 看数据 → 建训练 → 看效果",这一步把过程中的发现固化为一条条原则,下次再遇到同类情境时能回看提醒自己。

阶段 0 已把 Principle 数据层全建好(实体四软关联无外键、DAO/Repository 全套 CRUD),本阶段主要是两个新页面(编辑/列表)+ 两处入口衔接,数据层增量极少(见设计文档)。

## 范围

做:

- 记录原则(R-012):内容必填,四个关联(领域/错误类型/训练项/样本)可选。
- 查看原则列表(R-012):全部原则,按创建时间倒序,展示关联名。
- 修改原则(R-012):编辑已有原则的内容与关联。
- 删除原则(R-012):确认对话框(R-014)。
- 入口衔接:
  - 周复盘页顶部加「原则库」入口 → 原则列表页。
  - 领域页 F4「近期原则」可点 → 进编辑页(预填该原则)。

不做(留后续):

- 原则导出 → 阶段 7
- AI 自动生成原则 → MVP 外(N-006)
- 原则分类 / 标签 / 置顶 / 搜索 → MVP 外(N-004 不过度复杂)
- 样本详情页(训练项/样本关联的完整预填入口)→ 本阶段训练项/样本关联仅预填预留,不暴露选择器(见 D3)

## 用户场景

1. **从领域沉淀原则**:领域页 F4「近期原则」看到一条旧原则"边界先列清单",想补充措辞 → 点它进编辑页,改内容保存。
2. **新建原则**:周复盘页顶部点「原则库」→ 进原则列表 → 点新建 → 写"压力下先回位再选球",关联领域"羽毛球"+错误类型"压力下急躁",保存。
3. **回看原则提醒**:再次进原则库,看到之前沉淀的几条原则,按创建时间倒序排列,提醒自己下次怎么做。
4. **删过时原则**:原则库列表里长按或点删除某条已不适用的原则 → 弹确认 → 删除。
5. **空态**:还没沉淀任何原则,原则库显示引导"从最近的复盘中,把可迁移的认知写下来"。
6. **关联容错**:某原则关联的错误类型被删了,列表/编辑页不崩,显示"已删除"或隐藏该关联。

## 功能点

### F1 原则编辑页(新建 / 编辑共用)

- 入口:
  - 新建:原则列表页「新建」按钮(不预填);未来从训练效果页/样本详情进入时可预填训练项/样本(本阶段预留)。
  - 编辑:领域页 F4 点原则行(principleId 预填)、原则列表页点原则(principleId 预填)。
- 字段:
  - 原则内容(必填,一句话或一段)
  - 领域(可选,chips 选已有可见领域)
  - 错误类型(可选,chips 选已有错误类型)
  - 训练项(可选,本阶段不暴露选择器,仅预填入口带入时展示)
  - 样本(可选,本阶段不暴露选择器,仅预填入口带入时展示)
- 自动字段:`createdAt = now`(新建时,编辑不可改)。
- 必填校验:原则内容非空时才能保存。
- 保存:新建调 create,编辑调 update(保留原 createdAt);保存后返回来源页。
- 新建/编辑共用一页,按 principleId 判断(D2)。

### F2 原则列表页

- 数据:全部原则,按 createdAt 倒序。
- 每项展示:原则内容 + 创建时间 + 关联名(领域名 / 错误类型名,若有)。
- 交互:
  - 点原则 → 进编辑页(principleId 预填)。
  - 每项有删除入口 → 触发 F3。
  - 顶部「新建」按钮 → 进 F1 编辑页(不预填)。
- 空状态:无原则 → 引导"从最近的复盘中,把可迁移的认知写下来"。

### F3 删除原则

- 触发:原则列表页某项的删除入口。
- 交互:弹 `AlertDialog`,确认后调 `delete(principle)`,返回列表。
- 取消则不删。
- 原则是末端对象(无表引用它),无需引用检查,直接确认删(R-014 防误删)。

### F4 入口衔接

- 周复盘页顶部(PageHeader 区,与「训练项」入口并列)加「原则库」入口 → `onNavigateToPrincipleList` → PrincipleListScreen(D1)。
- 领域页 F4「近期原则」每项可点 → `onNavigateToPrincipleEdit(principleId)` → 进编辑页预填(D4,阶段 3 设计已预留)。
- 以上两处当前(阶段 3/5)为静态/无入口,阶段 6 接成可点。

### F5 关联容错

- 四个关联均为可选软关联(无外键约束)。关联对象被删时,原则保留。
- 列表页/编辑页展示关联名时,对缺失引用容错:查不到名则显示"已删除"或隐藏该关联行,不崩。

## 边界与约束

- **四关联可选软关联无外键**:domainId/errorTypeId/trainingId/sampleId 皆 Long?,不加外键约束。关联对象被删时原则保留(对齐 [Principle 实体](../android/app/src/main/java/com/growthos/app/data/local/entity/Principle.kt)注释)。UI 层容错(D5)。
- **内容必填**:原则内容非空才能保存。四关联全可选。
- **createdAt 创建时定不可改**:新建时 `now`,编辑时保留原值。编辑只改内容与关联(D2)。
- **删除直接确认**:原则是末端对象,无表引用它,不需引用检查,AlertDialog 确认即删(R-014)。
- **训练项/样本关联本阶段不暴露选择器**:数量可能多,chips 不适合;仅预留预填入口(从训练效果页/样本详情进入时带入)。本阶段样本详情页未建,故这两个关联实际只能为空,完整闭环留后续(D3)。
- **空态不阻断**:列表空显示引导,不报错。

## 验收标准

对齐 [MVP 需求文档](MVP需求文档.md) 验收标准 8(记录并查看原则)+ 第一阶段使用验证标准 6(沉淀 ≥3 原则)。

1. 能从周复盘页顶部进入原则库列表。
2. 能新建原则,内容必填,可选关联领域/错误类型,保存后出现在列表。
3. 能查看原则列表,按创建时间倒序,展示关联名。
4. 能修改已有原则(从列表或领域页 F4 进入),保存后内容更新且 createdAt 不变。
5. 能删除原则,确认后从列表消失。
6. 关联的错误类型/领域被删时,原则不崩,容错展示。
