# GrowthOS Android App 技术方案设计

> 本文档基于《产品定位》与《MVP 需求文档》产出，只描述技术实现方案，不改动产品需求。所有需求编号（R-001 ~ R-014）与原文档对齐。

## 0. 前置说明与待核实项

我的知识截止到 2026 年 1 月，而 Android 16 于 2026 年 5 月才正式发布。下列涉及 Android 16 与各库具体版本号的内容，需要你在装机或首次同步 Gradle 时核对并以实际可编译版本为准：

- Android 16 的 API level 数字（下文暂记为 `36`，按往届 Q→R→S→T→U→V→W→16 的递增推测，需核对）。
- Android Gradle Plugin (AGP)、Kotlin、KSP、Compose BOM、Room 的最新稳定版本号。
- Android 16 中可能影响本 App 的行为变更（前台服务、通知权限、后台限制、隐私沙盒等）。本 App 纯本地、无后台、无网络，受影响面预计很小，但仍需在首次构建后过一遍官方迁移清单。

文末「附录 A」列出了需要逐项核对的清单。

## 1. 技术选型

### 1.1 整体栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Kotlin | 官方首选语言，Compose 与 Coroutines 深度集成。 |
| 最低 SDK | API 26 (Android 8.0) | 覆盖绝大多数在用设备；产品定位文档要求本地优先、低摩擦，无需更高下限。 |
| 目标 SDK | API 36 (Android 16) | 目标机型为 Android 16，按官方要求 target 最新。 |
| 构建 SDK | API 36 | 同上。 |
| UI | Jetpack Compose + Material 3 | 声明式 UI，单 Activity 多 Screen，适合 MVP 快速迭代。 |
| 导航 | Navigation Compose | 官方导航方案，类型安全路由。 |
| 数据库 | Room (SQLite) | 本地优先、结构化数据、支持导出，符合 N-005 可迁移要求。 |
| 依赖注入 | 手动轻量 DI（不引入 Hilt） | MVP 模块少，手动构造 + Application 持有即可，降低构建复杂度。 |
| 异步 | Kotlin Coroutines + Flow | Room 原生返回 Flow，Compose 直接 collect。 |
| 序列化 | kotlinx.serialization | 导出 JSON、读取导入用。 |

### 1.2 关键决策理由

- **不引入 Hilt/Koin**：MVP 只有 5 张左右表、4 个页面层级，手动 DI 在 `Application` 里建一个 `AppContainer` 即可，省去 kapt/ksp 注解处理器的构建时间和学习成本。
- **不用 DataStore 替代 Room**：核心是「样本列表 + 按错误类型聚合统计」，关系型查询更直接；DataStore 只用于少量设置项（如默认领域、主题）。
- **不引入网络层**：MVP 明确不做云同步、账号，因此没有 Retrofit/OkHttp/Ktor。

## 2. 模块与目录结构

单 module 结构，MVP 阶段不拆分多 module，避免过早工程化。

```
app/
└── src/main/
    ├── AndroidManifest.xml
    ├── kotlin/com/growthos/app/
    │   ├── GrowthOSApp.kt              # Application，持有 AppContainer
    │   ├── MainActivity.kt             # 唯一 Activity，承载 Compose
    │   ├── di/
    │   │   └── AppContainer.kt         # 手动 DI 容器
    │   ├── data/
    │   │   ├── local/
    │   │   │   ├── GrowthOSDatabase.kt # Room database
    │   │   │   ├── entity/             # 表实体
    │   │   │   ├── dao/                # 数据访问对象
    │   │   │   └── relation/           # 带关系的 POJO（如带错误类型名的样本）
    │   │   ├── repository/             # 仓储层，封装 DAO
    │   │   └── export/                 # JSON 导出/导入
    │   ├── domain/
    │   │   └── model/                  # 领域枚举与值对象（Attribution、Emotion 等）
    │   ├── ui/
    │   │   ├── theme/                  # Material 3 主题、配色、字号
    │   │   ├── navigation/             # 路由定义、NavHost
    │   │   ├── record/                 # 今日记录页 + 样本录入
    │   │   ├── domain_view/            # 领域页
    │   │   ├── weekly/                 # 周复盘页
    │   │   ├── training/               # 训练项管理
    │   │   ├── principle/              # 原则库
    │   │   └── components/             # 复用组件
    │   └── util/
    │       └── TimeUtil.kt
    └── res/
```

### 2.1 分层职责

- **data 层**：实体、DAO、Repository、导出。Repository 对 UI 暴露 `Flow<List<...>>`，UI 不直接碰 DAO。
- **domain 层**：纯 Kotlin 枚举与值对象，无 Android 依赖。归因类型、训练状态、情绪强度范围定义在此。
- **ui 层**：每个页面一个目录，含 `XxxScreen.kt` 与 `XxxViewModel.kt`。ViewModel 用 `viewModelScope` 调 Repository，状态用 `StateFlow` 暴露。

## 3. 数据模型设计

### 3.1 实体关系总览

```
Domain 1───* Sample *───1 ErrorType
  │            │
  │            │ (Sample 关联归因枚举，不建表)
  │            │
  │            *───? Emotion (内嵌字段，非独立表)
  │
  ├───* Training *───1 ErrorType
  │
  └───* Principle *───? (可选关联 Domain / ErrorType / Training / Sample)
```

ErrorType 跨领域复用（R-004），所以它不挂在 Domain 下，而是独立表；Sample 和 Training 都通过 `errorTypeId` 引用它。归因类型是固定枚举（R-005），用 Room 的 `TypeConverter` 存为字符串，不建独立表。

### 3.2 表结构（Entity）

#### Domain（领域）— 对应 R-001

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long (PK, autoGenerate) | 主键 |
| name | String | 领域名称 |
| createdAt | Long (epoch millis) | 创建时间 |
| hidden | Boolean | 是否隐藏（R-001 允许停用/隐藏） |

#### ErrorType（错误类型）— 对应 R-004

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long (PK) | 主键 |
| name | String | 唯一，跨领域复用 |
| createdAt | Long | 创建时间 |

`name` 加唯一索引，避免重复创建相似错误类型。

#### Sample（样本）— 对应 R-002 / R-003 / R-006

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long (PK) | 主键 |
| domainId | Long (FK → Domain) | 所属领域 |
| recordedAt | Long | 记录时间 |
| result | String | 结果（自由文本，R-003） |
| description | String | 一句话描述 |
| errorTypeId | Long (FK → ErrorType) | 主要错误类型 |
| attribution | String (enum) | 归因类型，TypeConverter |
| emotionIntensity | Int? | 情绪强度 1~5，可空（R-006） |
| review | String | 一句话复盘：下次怎么做 |

索引：`(domainId, recordedAt DESC)` 用于领域页与列表；`errorTypeId` 用于按错误类型统计与筛选。

#### Training（训练项）— 对应 R-010

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long (PK) | 主键 |
| domainId | Long (FK → Domain) | 所属领域 |
| errorTypeId | Long (FK → ErrorType) | 关联错误类型 |
| goal | String | 训练目标 |
| acceptanceCriteria | String? | 验收标准，可选 |
| startedAt | Long | 开始时间 |
| endedAt | Long? | 结束时间，进行中为 null |
| status | String (enum) | 进行中 / 已完成 / 已放弃 |
| note | String? | 备注 |

#### Principle（原则）— 对应 R-012

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long (PK) | 主键 |
| content | String | 原则内容 |
| createdAt | Long | 创建时间 |
| domainId | Long? | 可选关联 |
| errorTypeId | Long? | 可选关联 |
| trainingId | Long? | 可选关联 |
| sampleId | Long? | 可选关联 |

### 3.3 枚举定义（domain 层）

```kotlin
enum class Attribution(val label: String) {
    CONTROLLABLE("可控错误"),
    UNCONTROLLABLE("不可控波动"),
    OPPONENT_EXTERNAL("对手或外部强"),
    ENVIRONMENT("环境问题")
}

enum class TrainingStatus(val label: String) {
    IN_PROGRESS("进行中"),
    COMPLETED("已完成"),
    ABANDONED("已放弃")
}
```

情绪强度约束为 1~5，UI 层用 `Slider` 或 5 档选择器保证输入合法，数据库不存非法值。

### 3.4 种子数据

首次启动时插入 R-004 列出的 8 个示例错误类型（边界条件遗漏、信息不足就行动等），作为引导。归因类型是枚举，无需种子。

## 4. 页面结构与导航

### 4.1 导航图

底部导航三个主入口，其余为子页面跳转：

```
BottomBar
├── 今日记录 (Record)        ← 启动默认页（产品定位 8.1：打开即记录）
├── 领域 (Domains)
│   └── 领域详情 (DomainDetail)   ← 领域页 8.2
└── 复盘 (Review)
    ├── 周复盘 (Weekly)           ← 8.3
    ├── 训练项列表 (TrainingList)
    │   └── 训练效果 (TrainingEffect)  ← R-011
    └── 原则库 (PrincipleList)    ← 8.4

其他入口：
- 样本录入/编辑 (SampleEdit)       ← 从今日记录、领域详情进入
- 领域创建/编辑 (DomainEdit)
- 错误类型选择/新增 (ErrorTypePicker)
- 设置（导出/导入/关于）
```

### 4.2 各页面要点

- **今日记录页**：顶部为「快速记录」入口（大按钮，30 秒内能进录入流程），下方为今日样本列表。下拉可切换默认领域。
- **样本录入页**：字段顺序按记录摩擦从低到高排——领域（默认选中）→ 结果 → 一句话描述 → 错误类型（优先展示已有，支持新增）→ 归因（四选一 chips）→ 情绪强度（可选，默认不填）→ 一句话复盘。必填校验：领域、结果、错误类型、归因、复盘（情绪强度可选）。字段数 ≤ 8，满足验收标准第 10 条。
- **领域页**：最近样本、错误类型分布（简单条形）、当前训练项、近期原则。统计全部由 Room 聚合查询产生，不在 UI 层算。
- **周复盘页**：时间范围选择器（最近 7 天 / 最近 N 条），展示 R-009 要求的五项。跨领域与单领域切换。
- **训练效果页**：训练开始前/后该错误类型出现次数 + 训练后相关样本列表（R-011）。
- **原则库**：列表 + 编辑，支持可选关联。

## 5. 核心闭环的技术映射

MVP 闭环 8 步与实现的对应关系：

| 闭环步骤 | 实现点 |
|---|---|
| 1. 选领域 | DomainEdit 创建；SampleEdit 选择 |
| 2. 记样本 | SampleEdit + SampleDao.insert |
| 3. 错误类型 | ErrorTypePicker，优先展示已有，支持新增并立即选中 |
| 4. 标归因 | 四选一 chips，枚举保证不跑偏 |
| 5. 周汇总 | Room 聚合查询：按 errorTypeId 分组 count，按时间窗口过滤 |
| 6. 建训练项 | TrainingEdit，从高频错误入口带出 errorType 预填 |
| 7. 训练前后对比 | TrainingEffect 页：`SELECT COUNT(*) FROM sample WHERE errorTypeId=? AND recordedAt < training.startedAt` 与 `> startedAt` |
| 8. 沉淀原则 | PrincipleEdit，可选关联 |

## 6. 关键查询（Room）

需求中所有统计都可在 SQL 层完成，避免把全表拉进内存：

- 高频错误前三：`SELECT errorTypeId, COUNT(*) c FROM sample WHERE domainId=? AND recordedAt BETWEEN ? AND ? GROUP BY errorTypeId ORDER BY c DESC LIMIT 3`
- 可控错误占比：分母 `COUNT(*)`，分子 `COUNT(*) WHERE attribution='CONTROLLABLE'`，单条 SQL 出两个值。
- 情绪强度最高：`SELECT * FROM sample WHERE domainId=? AND recordedAt BETWEEN ? AND ? ORDER BY emotionIntensity DESC NULLS LAST LIMIT 1`
- 训练前后对比：两条 COUNT 查询 + 一条列表查询。

## 7. 数据导出与导入（R-013）

- 导出：用 `kotlinx.serialization` 把全部表序列化为一个 JSON 对象，通过 Android `FileProvider` + `ACTION_SEND` 或 `CREATE_DOCUMENT` 保存到用户选定位置（系统存储访问框架 SAF，无需申请存储权限，符合 Android 13+ 的 scoped storage 趋势与 Android 16 隐私方向）。
- 导出内容包含：domains、errorTypes、samples、trainings、principles，外加一个 `meta`（版本号、导出时间），便于后续迁移。
- 导入（可选，MVP 可只做导出）：读取 JSON 校验后批量入库，遇主键冲突按「导入为新记录」策略避免覆盖。

## 8. 数据安全（R-014）

- 所有删除操作在 UI 层弹确认对话框（Compose `AlertDialog`），确认后才调 DAO。
- Room 外键不加 `ON DELETE CASCADE`：删除领域前要求先迁移或删除其下样本，避免误删连锁。删除错误类型前检查是否被样本/训练引用，被引用则提示「N 条样本在用，无法删除」而非静默删除。
- 提供「最近删除」不在 MVP 范围；用确认对话框 + 引用检查作为防误删手段。

## 9. 主题与无障碍

- Material 3 动态取色（Android 12+ `dynamicColorScheme`），Android 16 上自动跟随系统主题；低版本回退到预设配色。支持深色模式。
- 文本对比度遵循 Material 3 默认值；情绪强度、归因 chips 用颜色+文字双重编码，不只靠颜色。
- 字号跟随系统设置（Compose 默认支持 sp 缩放）。

## 10. 测试策略

- **单元测试**：Repository 与聚合查询逻辑（用 Room in-memory DB），归因/状态枚举约束，导出 JSON 的序列化往返。
- **UI 测试**：样本录入闭环（创建领域 → 录样本 → 列表出现），用 Compose UI Test。
- **手动验收**：按文档「8. 验收标准」10 条逐条过；按「9. 第一阶段使用验证标准」真机自用 2~4 周。

## 11. 开发顺序建议

按闭环可验证性从内到外，每一步都可单独跑通：

1. 工程骨架：Gradle、Manifest、Application、MainActivity、空导航、主题。
2. 数据层：所有 Entity / DAO / Database / Repository + 单测。
3. 领域管理（R-001）：建领域、列表、隐藏。
4. 样本记录闭环（R-002~R-006, R-007）：录入、列表、筛选，含错误类型新增复用。
5. 领域复盘视图（R-008）。
6. 周复盘（R-009）。
7. 训练项与效果观察（R-010, R-011）。
8. 原则沉淀（R-012）。
9. 导出导入（R-013）。
10. 数据安全确认弹窗与引用检查（R-014）打磨。
11. 真机自用验证。

## 12. 不在 MVP 范围（与需求文档第 7 节一致）

账号、云同步、社区、AI、视频/截图上传、复杂图表、积分等级、付费、模板库——本期一律不实现。

## 附录 A：需核对项清单（Android 16 / 版本号）

下列在首次构建前需用最新官方文档或 Android Studio 的 SDK Manager / lint 提示核对：

1. Android 16 的 API level 数字，确认 `compileSdk` / `targetSdk` 取值。
2. AGP 与 Kotlin、KSP 版本组合的兼容矩阵。
3. Compose BOM 最新稳定版（决定 `androidx.compose.*` 各库版本）。
4. Room 最新稳定版及 KSP 版本。
5. Android 16 行为变更清单中，与本 App 相关项：前台服务（本 App 无前台服务，预计无影响）、通知（本 App 无通知，预计无影响）、存储权限（导出走 SAF，预计无影响）、16KB 页面大小对原生库的影响（Room/SQLite 需确认依赖已适配）。
6. `FileProvider` / SAF (`CREATE_DOCUMENT`) 在 Android 16 上是否有新限制。
