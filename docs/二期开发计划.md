# GrowthOS 二期开发计划

## Context

一期完成了 app 工程骨架与"复盘手册"风格 UI:主题/字体/组件库([Theme.kt](../android/app/src/main/java/com/growthos/app/ui/theme/Theme.kt)、[Type.kt](../android/app/src/main/java/com/growthos/app/ui/theme/Type.kt)、[Ledger.kt](../android/app/src/main/java/com/growthos/app/ui/components/Ledger.kt)),三个展示页([RecordScreen](../android/app/src/main/java/com/growthos/app/ui/record/RecordScreen.kt)/[DomainScreen](../android/app/src/main/java/com/growthos/app/ui/domain_view/DomainScreen.kt)/[WeeklyScreen](../android/app/src/main/java/com/growthos/app/ui/weekly/WeeklyScreen.kt))和底部导航。但全部是 [SampleStub](../android/app/src/main/java/com/growthos/app/domain/model/SampleStub.kt) 假数据,`data/` 层一行未建,没有任何录入页,无法记录真实样本。

本文件是**二期开发计划文档**,定位为 docs/ 下与现有三份文档并列的第四份,记录"下一步做什么、按什么顺序、每步产出什么、怎么验收"。需求仍以 R-001~R-014 为准,本文件不重复需求,只规划落地节奏。

## 分阶段计划

按闭环可验证性从内到外,每一步都能单独跑通。每个阶段对应技术方案 §11 的一个开发步骤。

### 阶段 0:数据层骨架(技术方案 §11.2 / R-002 表结构)

落地 Room 全套,这是后续一切的前提。参考 [技术方案设计 §3.2](技术方案设计.md) 的表结构。

产出:
- `data/local/entity/`:Domain、ErrorType、Sample、Training、Principle 五张实体,字段对齐 §3.2 表定义。
- `data/local/dao/`:各表 DAO。Sample DAO 含 §6 的聚合查询(高频前三、可控占比、情绪最高、训练前后对比)。
- `data/local/GrowthOSDatabase.kt`:Room database,外键约束开启,`TypeConverter` 处理 Attribution/TrainingStatus 枚举。
- `data/local/entity/relation/`:带错误类型名的样本 POJO(SampleWithErrorType)。
- `data/repository/`:五个 Repository,对 UI 暴露 `Flow<List<...>>`。
- `di/AppContainer.kt`:手动 DI 容器,持 Database 与各 Repository 单例([MainActivity](../android/app/src/main/java/com/growthos/app/MainActivity.kt) 从 Application 取)。
- `GrowthOSApp.kt`([Application](../android/app/src/main/java/com/growthos/app/GrowthOSApp.kt))持有 AppContainer。
- 首次启动种子数据:R-004 的 8 个示例错误类型。
- 单测:Repository + 聚合查询,用 Room in-memory DB。

验收:单测通过;app 能启动不崩(此时 UI 仍用假数据)。

验收:能新建 3 个领域,DomainScreen chips 反映真实领域(R-001 / 验收标准 1)。

### 阶段 2:样本记录闭环(R-002~R-007 / 技术方案 §11.4)★ 核心

闭环第 2~4 步。这是 MVP 心脏,做完"记一条 → 今日列表出现"。

**录入页结构决策:单页 + 内联选择。** 领域、错误类型均在 SampleEdit 单页内联展开,不跳独立路由页,把记录摩擦压到最低(对齐 N-001)。新建错误类型用底部对话框/弹层完成并立即选中。

产出:
- `ui/record/SampleEditScreen.kt` + `SampleViewModel.kt`:录入/编辑样本。
  - 字段顺序按记录摩擦从低到高(技术方案 §4.2):领域(默认选中,内联下拉/chips)→ 结果 → 一句话描述 → 错误类型(内联选择,优先展示已有)→ 归因(四选一 chips)→ 情绪强度(可选,1~5)→ 一句话复盘。
  - 必填校验:领域、结果、错误类型、归因、复盘(情绪可选)。字段数 ≤ 8(验收标准 10)。
  - 删除:确认对话框(R-014)。
- `ui/record/ErrorTypePickerInline.kt`:错误类型内联选择组件(R-004)。优先展示已有,支持"新建并立即选中"——这是闭环第 3 环的产品价值,跨领域复用。新建走底部对话框。
- `ui/record/AttributionChips.kt`:四选一 chips,枚举固化(R-005),用 [Ledger.kt](../android/app/src/main/java/com/growthos/app/ui/components/Ledger.kt) 的琥珀强调色标"可控错误"。
- [RecordScreen.kt](../android/app/src/main/java/com/growthos/app/ui/record/RecordScreen.kt) 今日样本列表接 `SampleRepository.observeToday()`,替换 SampleStub.examples。快速记录按钮 → SampleEdit。
- 样本详情页(R-002 要求可查看):点击列表项进入,只读展示。

验收:任意领域下录样本 → 今日列表出现;可改可删;复用已有错误类型与新建错误类型都能工作(验收标准 2/3/4/10)。

## 优先级与取舍

- **第一步从阶段 0 数据层开始。** Room 全套 + 单测是后续一切的前提,做完才接得上真数据。文档覆盖 0~8 全部阶段,但实际动手按 0→1→2 阻塞链推进。
- **阶段 0~2 是阻塞链**:数据层 → 领域 → 录入。没有前一个,后一个没法做。这三阶段做完,闭环就成立了,后面的 3~7 都是"看数据"的不同切面,可并行或调序。
- **SampleEdit 是单点最高价值**:闭环第 2~4 环全压在这一页,字段设计直接决定 N-001(30 秒~2 分钟)能否达成。值得花最多时间打磨字段顺序与默认值。
- **ErrorTypePicker 的"新建并立即选中"不能省**:R-004 跨领域复用的产品价值全靠这个交互,否则用户会重复创建相似错误类型,污染统计。
- **dynamicColor 取舍**:[Theme.kt](../android/app/src/main/java/com/growthos/app/ui/theme/Theme.kt) 当前 `dynamicColor` 默认 false(保手册配色稳定),与产品定位 §9 的"Android 12+ 走 dynamicColor"有出入。阶段 7 做设置页时把它做成用户可切换的开关,两全。
- **Preview 拆分**:阶段 2 起,把现有四个 `@Preview` 从 [GrowthOSApp.kt](../android/app/src/main/java/com/growthos/app/ui/navigation/GrowthOSApp.kt) 拆到各自 Screen 旁,边写边看预览。
