## 数据层增量(本阶段唯一新增 DAO 方法)

R-012 的 CRUD 阶段 0 已备齐,唯一缺口是**原则列表页要展示关联名(领域名 + 错误类型名)**,现有 `observeAll` 只返回 Principle 裸数据。补一个 LEFT JOIN 查询(软关联可 null,故 LEFT JOIN):

```kotlin
// PrincipleDao
@Query("""
    SELECT p.*, d.name AS domainName, et.name AS errorTypeName
    FROM principles p
    LEFT JOIN domains d ON p.domainId = d.id
    LEFT JOIN error_types et ON p.errorTypeId = et.id
    ORDER BY p.createdAt DESC
""")
fun observeAllWithNames(): Flow<List<PrincipleWithNames>>
```

新增 POJO `PrincipleWithNames`(@Embedded principle + domainName: String? + errorTypeName: String?),对齐 [SampleWithErrorType](../android/app/src/main/java/com/growthos/app/data/local/relation/SampleWithErrorType.kt) / [TrainingWithNames](../android/app/src/main/java/com/growthos/app/data/local/relation/TrainingWithNames.kt) 模式。LEFT JOIN 因软关联可 null——关联对象被删时 domainName/errorTypeName 为 null,UI 容错(D5)。

`trainingId` / `sampleId` 关联太稀疏且本阶段不暴露选择器(D3),列表页不展示,故不 JOIN。进编辑页才见(编辑页按需 getById 解析)。

`PrincipleRepository.observeAllWithNames()` 透传。现有 `observeAll`(裸数据)保留,领域页 F4 继续用。

## 数据流

```
PrincipleEdit:
  init(if editing) getById → 预填 form
  用户填字段 → canSave 变 → 点保存 →
    新建: create(content, domainId?, errorTypeId?, trainingId?, sampleId?)
    编辑: update(existing.copy(...))  // 保留 createdAt
  → emit Saved → onBack

PrincipleList:
  observeAllWithNames() Flow → principles → 列表渲染
  点原则 → onNavigateToPrincipleEdit(principleId)
  点删除 → AlertDialog 确认 → delete(principle) → Flow 自动刷新
```

## 关键决策

### D1 原则库入口挂复盘 Tab 下,周复盘页顶部加入口

技术方案导航树把 PrincipleList 挂「复盘」Tab(与 Weekly / TrainingList 并列)。复盘 Tab 当前直达 WeeklyScreen,阶段 5 已在其顶部加「训练项→」入口,阶段 6 同位置加「原则库→」入口。保持三底部 Tab 不变。原则是跨领域的全局沉淀,入口放全局视角的周复盘页比放单领域页合理。

### D2 编辑页新建/编辑共用一页

按 principleId 判断(null/非正=新建,正=编辑预填),对齐阶段 2 SampleEdit 范式。R-012 明确要求"系统必须允许用户修改原则",故编辑必须有——这点与阶段 5 训练项"只新建不编辑"不同,因为训练项是进行中的阶段性目标(改目标不如结束重建),而原则是可迁移认知,措辞会随理解深化而调整,编辑是常态。`createdAt` 创建时定不可改,编辑保留原值。

### D3 领域/错误类型用 chips,训练项/样本靠预填不暴露选择器

R-012 关联可选,四字段皆 Long?。领域/错误类型数量有限,用 chips 选(对齐 SampleEdit 的领域 chips + 错误类型 chips 范式)。训练项/样本数量可能多,chips 不适合,本阶段不暴露选择器,仅在从"训练效果页/样本详情"进入时预填 trainingId/sampleId。本阶段样本详情页未建,故这两个关联实际只能为空——完整预填闭环留后续(样本详情页或训练效果页加入口)。内容必填。

### D4 领域页 F4 原则可点进编辑

阶段 3 设计已预留"F4 原则点击:留阶段 6"。点 F4 原则行 → 进编辑页(principleId 预填)。这是闭环第 8 步在领域维度的衔接:用户在领域页看到旧原则,想改就直接点进去,不用绕到原则库找。

### D5 删除确认 + 关联容错

删原则前 AlertDialog 确认(R-014)。原则是末端对象——无表引用它(不像领域/错误类型被样本引用),不需引用检查,直接确认删即可。四个软关联在列表/编辑展示时对缺失引用容错:LEFT JOIN 返回 null 名则隐藏该关联段,不崩。对齐 Principle 实体"无外键约束,关联对象删时原则保留"的语义。

### D6 列表页加 observeAllWithNames JOIN 领域名+错误类型名

现有 observeAll 只返回 Principle 裸数据,列表页要展示"编程 · 边界条件遗漏"需关联名。加 LEFT JOIN 查询带领域名+错误类型名(LEFT JOIN 因软关联可 null),对齐阶段 5 TrainingWithNames 模式。trainingId/sampleId 关联太稀疏不 JOIN,列表页不展示。这是阶段 6 唯一数据层增量。observeAll(裸数据)保留,领域页 F4 继续用(它只需内容+时间)。
