## 状态设计(DomainViewModel)

```kotlin
data class DomainUiState(
    val domains: List<Domain> = emptyList(),   // 可见领域
    val hiddenDomains: List<Domain> = emptyList(), // 已隐藏领域
    val selectedId: Long? = null,              // 当前选中,null=空状态
    val dialog: DomainDialog? = null           // null=对话框关闭
)

sealed class DomainDialog {
    data object Create : DomainDialog
    data class Edit(val domain: Domain) : DomainDialog
}
```

- `domains` / `hiddenDomains`:collect `observeVisible()` 与 `observeAll()`(后者过滤 hidden)。
- `selectedId`:初始从 `SelectedDomainStore` 读;domains 变化时若 selected 不在可见列表则回退到第一个可见;切换时写回 Store。
- `dialog`:对话框开关 + 携带编辑目标(Create / Edit)。
- 保存:对话框提交 → `create(name)` 或 `rename(id,name)` + 可选 `setHidden` → 关闭对话框;Flow 自动推送回 UI。

## 数据流

```
DomainRepository.observeVisible()  (Flow)
  → DomainViewModel.domains  (StateFlow)

新建/改名/隐藏:viewModel 函数 → repository suspend → DAO → Flow 自动推送回 UI
```

## 关键决策

### D1 领域编辑用对话框,不开独立路由

二期计划写了 `DomainEditScreen.kt`。本阶段偏离:用 `ModalBottomSheet` / `AlertDialog`。理由:领域只有 name 一个可编辑字段,开独立路由摩擦大于收益,且与阶段 2"录入低摩擦"理念一致。代价:若后续领域加描述 / 颜色等字段,需升级为独立页。标记为可演进点。

### D2 重名不阻断,软提示

Domain 表无 name 唯一索引([技术方案 §3.2](技术方案设计.md) 只给 ErrorType 加)。系统允许重名。本阶段:新建时若已有同名,软提示可继续创建,不阻断。理由:自用场景重名危害低;强制唯一会引入额外查询与冲突处理。可演进:若实际使用发现重名污染统计,再加唯一索引 + IGNORE(与 ErrorType 一致)。

### D3 隐藏 vs 删除

只做隐藏(R-001 should 级"停用或隐藏")。删除留阶段 7(需引用检查:删领域前要迁移 / 删其下样本,DAO 已备 `countByDomain`)。隐藏字段 `hidden` 已在阶段 0 实体里。

### D4 当前选中持久化用 DataStore

`selectedDomainId` 存 DataStore Preferences(非 Room)。理由:这是 UI 偏好状态,非业务数据;技术方案 §1.2 也说 DataStore 用于设置项(默认领域、主题)。`SelectedDomainStore` 封装 `intPreferencesKey`,暴露 `flow: Flow<Long?>` 与 `suspend fun set(id: Long?)`。

### D5 恢复隐藏领域的入口

本阶段在领域页底部做"已隐藏(N)"折叠区,展开可恢复。若实施时间紧,可降级为:只做隐藏,恢复入口随阶段 3 一起做——标记为可降级,不阻塞阶段 1 验收(验收第 4 条要求恢复,降级则该条推迟)。
