## 数据层增量(本阶段唯一新增 DAO 方法)

R-010/R-011 的查询阶段 0 已备齐,唯一缺口是**训练项列表页要展示全部训练项 + 错误类型名 + 领域名**,现有 `observeInProgressByDomainWithTypeName` 只按单领域 + 只进行中。补一个全量 JOIN 查询:

```kotlin
// TrainingDao
@Query("""
    SELECT t.*, et.name AS errorTypeName, d.name AS domainName
    FROM trainings t
    INNER JOIN error_types et ON t.errorTypeId = et.id
    INNER JOIN domains d ON t.domainId = d.id
    ORDER BY
      CASE t.status WHEN 'IN_PROGRESS' THEN 0 WHEN 'COMPLETED' THEN 1 ELSE 2 END,
      t.startedAt DESC
""")
fun observeAllWithNames(): Flow<List<TrainingWithNames>>
```

复用 [SampleWithErrorType](../android/app/src/main/java/com/growthos/app/data/local/relation/SampleWithErrorType.kt) 的双 JOIN 模式(一次取全,避免 N+1)。新增 POJO `TrainingWithNames`(@Embedded training + errorTypeName + domainName),对齐 `SampleWithErrorType`。排序:进行中在前、已完成次之、已放弃最后,同状态按 startedAt 倒序。

`TrainingRepository.observeAllWithNames()` 透传。其余 `effectStats` / `observeSamplesAfter` / `finish` / `create` 全现成,不动。

> 现有 `TrainingWithTypeName`(单领域、只进行中)保留,领域页 F3 继续用;列表页用新的 `TrainingWithNames`(全量、带领域名)。两者职责不同,不合并。

## 状态设计

### TrainingEditViewModel

```kotlin
data class TrainingEditUiState(
    val domainId: Long? = null,           // 必填,预填或用户选
    val errorTypeId: Long? = null,        // 必填,预填(F5/F2 入口)或用户选
    val goal: String = "",                // 必填
    val acceptanceCriteria: String = "",  // 可选
    val note: String = "",                // 可选
    val availableDomains: List<Domain> = emptyList(),
    val availableErrorTypes: List<ErrorType> = emptyList(),
    val canSave: Boolean = false          // domainId/errorTypeId/goal 非空
)
```

- 预填:从导航参数 `errorTypeId`(F5/F2 入口)带入,`domainId` 取 `SelectedDomainStore` 当前领域(无则空,用户选)。
- `canSave`:`domainId != null && errorTypeId != null && goal.isNotBlank()`。
- 保存:`create(Training(domainId, errorTypeId, goal, acceptanceCriteria.takeIf{blank}, now, null, IN_PROGRESS, note.takeIf{blank}))`,emit `Saved` 事件 → 返回。
- 不接收 `trainingId`(D4 不做编辑)。

### TrainingListViewModel

```kotlin
data class TrainingListUiState(
    val trainings: List<TrainingWithNames> = emptyList()  // 按状态+时间排序
)
```

- `observeAllWithNames()` → StateFlow。
- `finishTraining(id, status)`:调 `trainingRepository.finish(id, status)`,列表自动刷新(Flow)。
- 空态:`trainings.isEmpty()` → 引导文案。

### TrainingEffectViewModel

```kotlin
data class TrainingEffectUiState(
    val training: TrainingWithNames? = null,      // 训练项信息(目标/验收/状态/时间)
    val stats: TrainingEffectStats? = null,       // 前后 COUNT(一次性)
    val afterSamples: List<SampleWithErrorType> = emptyList()  // 训练后样本(Flow)
)
```

- 入参 `trainingId`。`init` 时:`getById(trainingId)` 取训练项(一次性),`effectStats(errorTypeId, startedAt)` 取前后计数(一次性),`observeSamplesAfter(errorTypeId, startedAt)` 订练后样本(Flow)。
- 三者用 `combine` 合成 UiState;`training`/`stats` 一次性值包成 `flowOf` 参与合并。
- `training` 为 null(被结束并……不存在)→ 显示错误态(理论不发生,列表点进来必有)。

## 数据流

```
TrainingEdit:
  用户填字段 → canSave 变 → 点保存 → create(Training(..., IN_PROGRESS)) → emit Saved → onBack

TrainingList:
  observeAllWithNames() Flow → trainings → 列表渲染
  点训练项 → onNavigateToEffect(trainingId)
  点结束 → 对话框 → finish(id, COMPLETED|ABANDONED) → Flow 自动刷新

TrainingEffect:
  combine(
    flowOf(training),                      // getById 一次性
    flowOf(stats),                         // effectStats 一次性
    observeSamplesAfter(errorTypeId, startedAt)  // Flow
  ) → UiState → 渲染前后 COUNT + 样本列表
```

## 关键决策

### D1 三个入口衔接全做

周复盘 F5 → 建训练项、周复盘 F2 行 → 建训练项、领域页 F3 → 效果页。理由:这是闭环第 5→6→7 步的衔接点,阶段 3 设计已注明 F3「留阶段 5」、阶段 4 的 F5 文案本就是"建议创建专项训练项"。三个入口让用户在任何看到高频错误的地方都能一键行动,闭环才连贯。

### D2 effectStats 维持 suspend,不改 Flow

训练开始时间 `startedAt` 固定,前后窗口语义不变,新样本进来只是 afterCount 变,但用户不会停在效果页等推送——离开再回来重新拉取即可。`observeSamplesAfter` 已是 Flow(样本列表适合实时),`effectStats` 若也改 Flow 反而要与样本 Flow 协调,混用增复杂度。对齐 R-011「展示基础对比」的最低要求。与阶段 4 周复盘 F1 选 Flow(D1)不矛盾:那里样本数是页内主指标需实时,这里效果对比是进页看一次。

### D3 结束用对话框选完成/放弃

`finish(id, status)` 支持三态,进行中只能转已完成或已放弃。完成(验收达成)与放弃(主动中止)语义不同,显式区分让用户对训练结果有诚实记录,后续回看能分辨"练成了"还是"没坚持"。状态变更属较重操作,对话框防误触,对齐 R-014 删除类操作要确认的思路。

### D4 只做新建+结束,不做编辑

不支持改已有训练项的目标/验收/备注。理由:R-010 只要求"创建 + 查看进行中 + 结束",编辑增加页面复杂度与测试面且 MVP 未要求(N-004 不过度复杂)。`startedAt` 也因此天然不可改(创建时定)。如需调整目标,用户可结束旧的再建新的,历史可查。`update` 方法 Repository 层保留(未来扩展),本阶段 UI 不调用。

### D5 训练项列表挂复盘 Tab 下,不新增底部 Tab

技术方案导航树把 TrainingList 挂在「复盘」下。复盘 Tab 当前直达 WeeklyScreen,阶段 5 在周复盘页顶部加"训练项"入口推进 TrainingListScreen。保持三底部 Tab(记录/领域/复盘)不变,避免导航膨胀。列表页是复盘 Tab 的子页面,返回回周复盘。

### D6 编辑页预填 errorType,领域取当前选中

从 F5/F2 带 `errorTypeId` 进入时预填错误类型(可改),领域取 `SelectedDomainStore` 当前领域(无则空,用户在编辑页选)。`startedAt = now` 自动,不暴露。字段顺序按记录摩擦从低到高(对齐阶段 2 范式):领域 → 错误类型 → 目标 → 验收(可选)→ 备注(可选)。
