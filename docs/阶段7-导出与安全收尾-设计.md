### 新建 ExportPayload + DataExporter

```kotlin
// data/export/ExportPayload.kt
@Serializable
data class ExportMeta(
    val version: Int = 1,
    val exportedAt: Long
)

@Serializable
data class ExportPayload(
    val domains: List<Domain>,
    val errorTypes: List<ErrorType>,
    val samples: List<Sample>,
    val trainings: List<Training>,
    val principles: List<Principle>,
    val meta: ExportMeta
)
```

```kotlin
// data/export/DataExporter.kt
class DataExporter(
    private val domainRepository: DomainRepository,
    private val errorTypeRepository: ErrorTypeRepository,
    private val sampleRepository: SampleRepository,
    private val trainingRepository: TrainingRepository,
    private val principleRepository: PrincipleRepository,
    private val now: () -> Long = TimeUtil::nowMillis
) {
    suspend fun export(): String {
        val payload = ExportPayload(
            domains = domainRepository.observeAll().first(),
            errorTypes = errorTypeRepository.observeAll().first(),
            samples = sampleRepository.observeAll().first(),
            trainings = trainingRepository.observeAllWithNames().first().map { it.training },
            principles = principleRepository.observeAll().first(),
            meta = ExportMeta(version = 1, exportedAt = now())
        )
        return Json { prettyPrint = true }.encodeToString(ExportPayload.serializer(), payload)
    }
}
```

> Training 全量:TrainingRepository 无 observeAll() 裸数据,有 observeAllWithNames(带 JOIN)。DataExporter 用 observeAllWithNames().map { it.training } 取裸 Training。或给 TrainingDao 加 observeAll()——但为复用现有,用 observeAllWithNames 取 .training 即可,不增量 DAO。

ErrorTypeRepository.referenceCount / delete 已有,不增量。

## 状态设计

### SettingsViewModel

```kotlin
sealed interface ExportState {
    data object Idle : ExportState
    data object Exporting : ExportState
    data class Ready(val json: String) : ExportState      // JSON 就绪,等 Screen 写入 Uri
    data object Success : ExportState
    data class Failed(val reason: String) : ExportState
}

data class SettingsUiState(
    val exportState: ExportState = ExportState.Idle
)
```

- `export()`:调 `DataExporter.export()` → emit `Ready(json)`。
- `onJsonConsumed()` / `onWritten()` / `onFailed(reason)`:Screen 写入 Uri 后回调,更新状态。
- ExportState 用 StateFlow(非 SharedFlow,因 Screen 要根据状态决定是否启动 SAF launcher)。

### SampleViewModel 错误类型删除扩展

```kotlin
sealed interface ErrorTypeDeleteEvent {
    data class Blocked(val referenceCount: Int) : ErrorTypeDeleteEvent  // 被引用拦截
    data object Deleted : ErrorTypeDeleteEvent
}
```

- `deleteErrorType(id)`:查 referenceCount,>0 emit Blocked(count);=0 调 delete + emit Deleted。
- 用 SharedFlow(一次性事件,UI 弹对话框 / 提示)。

## 数据流

```
导出:
  设置页点「导出数据」→ vm.export() → DataExporter.export()
  → 从五 Repository 拉全量 → 组装 ExportPayload → encode JSON
  → emit ExportState.Ready(json)
  → Screen 检测 Ready → 启动 CreateDocument launcher → 用户选 Uri
  → Screen 写入 json 到 Uri → vm.onWritten() → emit Success
  → 提示「已导出」
  (用户取消 launcher / 写入异常 → vm.onFailed() → 提示「导出未完成」)

错误类型删除:
  chip 长按 → vm.deleteErrorType(id)
  → referenceCount > 0 → emit Blocked(count) → UI 提示「N 条在用,无法删除」
  → referenceCount = 0 → UI 弹确认对话框 → 确认 → delete(id) → emit Deleted → chip 消失
```

## 关键决策

### D1 导出入口挂周复盘页顶部,新建设置页

技术方案提到「设置(导出/导入/关于)」作为其他入口,但当前无设置页。阶段 5/6 已在周复盘页顶部加「训练项→」「原则库→」入口,本阶段同位置加「设置→」→ SettingsScreen。保持三底部 Tab 不变。设置页本阶段只含「导出数据」,为后续关于 / 主题扩展预留。

### D2 只做导出,不做导入

R-013 只要求「至少一种导出格式」,技术方案 §7 明确「导入可选,MVP 可只做导出」。导入要读 JSON 校验 + 批量入库 + 主键冲突处理,工作量大且 MVP 未要求。导出 JSON 含 meta(版本号)为后续导入预留格式基础。留后续。

### D3 错误类型长按 chip 弹删除确认 + 引用检查

ErrorTypePickerInline 的 chip 加长按(复用阶段 1 领域 chip 长按范式)→ 查 `referenceCount`(阶段 0 已建)→ >0 拦截提示「N 条样本 / 训练项在用,无法删除」,=0 弹 AlertDialog 确认删。被引用的错误类型不可删,防误删连锁(R-014)。错误类型跨领域复用(R-004),删除影响面大,引用检查必要。

### D4 领域维持只隐藏不物理删除

阶段 1 决定领域用 hidden 字段停用,不物理删除。技术方案 §8「删领域前要求迁移 / 删除其下样本」不落地——因为根本不删领域。这是对技术方案的偏离,理由:领域是样本归属,物理删除会丢失历史样本的领域归属语义;隐藏已能满足「停用暂时不用的领域」的产品需求。文档声明此偏离。故领域无删除确认 / 引用检查流程。

### D5 导出走 SAF CREATE_DOCUMENT

用 `ActivityResultContracts.CreateDocument("application/json")` 让用户选保存位置,系统存储访问框架(SAF)处理权限,App 不申请存储权限。对齐技术方案 §7 + Android 13+ scoped storage + Android 16 隐私方向。ViewModel 生成 JSON 字符串,Screen 用 launcher 拿 Uri 写入。取消 launcher 不崩。

### D6 五表实体加 @Serializable + ExportPayload 包装

给五表实体加 `@Serializable`(kotlinx-serialization 阶段 0 已配依赖)。新建 ExportPayload 包装五表 + meta(版本号 / 导出时间)。DataExporter 从各 Repository 拉全量组装。这是唯一对现有实体的改动——注解只影响序列化,不影响 Room 映射。枚举 Attribution / TrainingStatus 自动支持。prettyPrint = true 便于用户可读与后续导入校验。
