# GrowthOS 阶段 5:训练项与效果观察 需求文档

## 文档定位

本文件是二期阶段 5(训练项与效果观察)的细化需求。需求基线以 [MVP 需求文档](MVP需求文档.md) R-010 / R-011 为准,本文件不重复原文措辞,只把它落地到可实施的交互与边界。技术实现见配套《阶段5-训练项与效果观察-设计》。前置依赖:阶段 0~4 已落地。

阶段 5 是闭环第 6~7 步——基于高频错误创建专项训练项,并观察训练前后该错误类型的出现情况。这是从"看数据"(阶段 3~4)走向"行动 + 验证"的转折:周复盘建议关注的错误、领域页的高频错误,都能一键变成训练项;训练开始后,继续记样本,就能在效果页看到这个错误是否在变少。

阶段 0 已把 R-010/R-011 的数据层几乎全建好(训练项 CRUD、三态状态机、前后 COUNT、训练后样本列表),所以本阶段主要是 UI 与入口衔接,数据层增量极少(见设计文档)。

## 范围

做:

- 基于错误类型创建训练项(R-010),从高频错误入口带出 errorType 预填。
- 训练项列表页:查看进行中 / 已完成 / 已放弃的训练项。
- 结束训练项(R-010):对话框选"已完成"或"已放弃"。
- 训练效果页(R-011):训练前后该错误类型出现次数 + 训练后相关样本列表。
- 三个入口衔接:
  - 周复盘 F5「建议关注」→ 建训练项(带错误类型预填)
  - 周复盘 F2「高频错误前三」每一行 → 建训练项(带错误类型预填)
  - 领域页 F3「当前训练项」→ 训练效果页
- 复盘 Tab 下挂训练项列表入口(周复盘页顶部加入口,不新增底部 Tab)。

不做(留后续):

- 修改已有训练项(改目标 / 验收标准 / 备注)→ 如需改,结束旧的再建新的(D4)
- 原则录入 / 列表 → 阶段 6
- 导出 → 阶段 7
- 删除训练项 → MVP 不做,只结束不删(对齐 R-014 防误删思路,历史训练项保留可查)
- AI 自动生成训练建议 → MVP 外(N-006)
- 自动判断训练是否成功 → MVP 外(R-011 明确"不需要自动判断")

## 用户场景

1. **从建议建训练**:周复盘看到"建议关注:边界条件遗漏(可控,本周 4 次)",点这个建议 → 进训练项编辑页,错误类型已预填"边界条件遗漏",填目标"涉及分支/边界先列清单再写代码",保存。训练项建立,开始时间记为当下。
2. **从高频错误建训练**:周复盘高频错误前三里点"压力下急躁 3 次" → 同样进编辑页预填该错误类型,建训练项。
3. **看训练效果**:领域页"当前训练项"区块点某个进行中的训练项 → 进训练效果页,看到"训练前 6 次 / 训练后 2 次"+ 训练后那 2 条样本列表,心里有数这个错误在变少。
4. **结束训练项**:训练项列表里点"结束" → 弹对话框选"已完成"或"已放弃",确认后训练项归档,记录结束时间。之后可在列表的"已完成/已放弃"分组里回看。
5. **进训练项列表**:复盘 Tab 进周复盘页,顶部点"训练项" → 看所有训练项列表,进行中的排在前。
6. **空态**:还没有任何训练项,列表页显示引导"从周复盘的高频错误开始,建第一个训练项"。效果页若训练后无样本,显示"训练后还没有记录该类错误,继续保持"。

## 功能点

### F1 训练项编辑页(新建)

- 入口:周复盘 F5 / F2(带 errorType 预填)、训练项列表页"新建"按钮(不预填)。
- 字段(按顺序):
  - 领域(必填,默认选中 SelectedDomainStore 当前领域或用户选)
  - 错误类型(必填,预填时带入不可为空;可改选已有或新增)
  - 训练目标(必填,一句话)
  - 验收标准(可选,怎么算练成)
  - 备注(可选)
- 自动字段:`startedAt = now`(不暴露给用户),`status = IN_PROGRESS`,`endedAt = null`。
- 必填校验:领域、错误类型、训练目标三者为空时禁用保存。
- 保存后返回来源页(周复盘或训练项列表)。
- 不做编辑已有训练项(D4)。

### F2 训练项列表页

- 数据:全部训练项(进行中 / 已完成 / 已放弃),按状态分组或分段展示,进行中排在前、按 startedAt 倒序;已完成/已放弃按 endedAt 倒序。
- 每项展示:错误类型名 + 训练目标 + 状态 + 开始时间(已结束的加结束时间)。
- 交互:
  - 点训练项 → 进训练效果页(F4)。
  - 进行中的训练项有"结束"按钮 → 触发 F3。
  - 顶部"新建"按钮 → 进 F1 编辑页(不预填)。
- 空状态:无训练项 → "从周复盘的高频错误开始,建第一个训练项"。

### F3 结束训练项

- 触发:训练项列表里进行中训练项的"结束"按钮。
- 交互:弹 `AlertDialog`,二选一——"已完成"(验收达成)/"已放弃"(主动中止)。确认后调 `finish(id, status)`,置状态 + 记 `endedAt = now`,返回列表。
- 取消则不变更。
- 不提供"删除",只结束(D4 / 边界)。

### F4 训练效果页

- 入口:训练项列表点训练项、领域页 F3 点进行中训练项。
- 展示:
  - 训练项信息:错误类型名、训练目标、验收标准(若有)、状态、开始时间、结束时间(若已结束)。
  - 前后对比:训练前该错误类型出现次数(`beforeCount`)+ 训练后出现次数(`afterCount`),两个大数字并排(复用 `LedgerMetric`)。
  - 训练后相关样本列表:`observeSamplesAfter(errorTypeId, startedAt)`,按时间倒序,复用领域页样本行样式。
- 空状态:训练后无样本 → "训练后还没有记录该类错误,继续保持"。训练前无样本(建训练项前没记过这个错误)→ beforeCount 显示 0,不阻断。

### F5 入口衔接(三处)

- 周复盘 F5「建议关注」区块:可点 → `onNavigateToCreateTraining(errorTypeId)`,带错误类型预填进 F1。
- 周复盘 F2「高频错误前三」每一行:可点 → 同上,带该行错误类型预填进 F1。
- 领域页 F3「当前训练项」每项:可点 → `onNavigateToEffect(trainingId)`,进 F4 效果页。
- 以上三处当前(阶段 3/4)均为静态展示,阶段 5 接成可点。

### F6 复盘 Tab 训练项入口

- 周复盘页顶部(PageHeader 区或其下)加"训练项"入口 → 推进 `TrainingListScreen`。
- 不新增第四个底部 Tab,保持三 Tab(记录 / 领域 / 复盘)不变。训练项列表是复盘 Tab 下的子页面。

## 边界与约束

- **startedAt 固定不可改**:训练开始时间在创建时定为 `now`,之后不可改(D4 不做编辑)。前后对比窗口以此为界。
- **前后窗口定义**:前窗口 `[0, startedAt)`,后窗口 `[startedAt, now]`。对齐 [TrainingDao.effectStats](../android/app/src/main/java/com/growthos/app/data/local/dao/TrainingDao.kt)(`recordedAt < startedAt` / `recordedAt >= startedAt`)。
- **effectStats 一次性**:进入效果页拉一次,不随新样本自动刷新(设计 D2)。继续记样本后回到效果页会重新拉取。
- **状态机**:进行中 → 已完成 / 已放弃(经 F3 对话框)。已结束的训练项不可再改状态(D4)。
- **不删除训练项**:MVP 只结束不删,历史训练项保留可查,对齐 R-014 防误删思路。
- **领域与错误类型外键**:训练项关联 Domain 与 ErrorType,删除领域/错误类型前检查引用(阶段 0 已建 `trainingReferenceCount`,本阶段不涉及删除流程,但约束存在)。
- **空态不阻断**:列表空、效果页训练后无样本,均显示引导/正面文案,不报错。

## 验收标准

对齐 [MVP 需求文档](MVP需求文档.md) 验收标准 6(基于错误类型创建训练项)/ 7(查看训练前后出现情况)。

1. 能从周复盘的高频错误(F5 建议 / F2 前三)一键进入训练项编辑页,错误类型预填。
2. 能创建训练项,必填领域 / 错误类型 / 训练目标,创建后出现在训练项列表"进行中"。
3. 能查看训练项列表,进行中 / 已完成 / 已放弃分组可见。
4. 能结束进行中的训练项,选"已完成"或"已放弃",结束后归档且记录结束时间。
5. 能从训练项列表或领域页进入训练效果页,看到训练前后该错误类型出现次数 + 训练后样本列表。
6. 训练效果页在训练后无样本时显示正面空态,不报错。
